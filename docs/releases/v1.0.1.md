Console web mobile pour serveur Proxmox : terminal tmux persistant, shell de chaque
conteneur, ressources des nœuds et actions marche/arrêt. Connexion avec les
identifiants Proxmox, interface au style de Proxmox VE.

**Cette release contient tout.** C'est la seule version publiée : les itérations
précédentes (0.2.x, 0.3.x) y sont regroupées. Voir le `CHANGELOG.md` du dépôt.

## Gestionnaire de fichiers (nouvel onglet)

Cinquième onglet en bas : **Fichiers**. On y envoie n'importe quel fichier depuis le
téléphone (app Fichiers d'iOS, appareil photo, glisser-déposer sur ordinateur), on le
renomme, on le télécharge ou on le supprime.

Surtout, un appui sur « Utiliser dans un conteneur » donne une **URL signée** (24 h)
et les commandes prêtes (`wget -qO …` ou `curl -fsSL … -o …`) vers le dossier de ton
choix — ou les colle directement dans le terminal du conteneur choisi. Le lien
fonctionne **sans cookie de session**, ce qui est indispensable depuis un LXC.

Côté serveur : envoi en flux vers un fichier temporaire puis renommage (pas de fichier
tronqué, jamais en mémoire), 512 Mo par fichier, refus si le disque est plein. Les
fichiers sont stockés à côté de `config.json` et **survivent à `update.sh`**.

## Pilotage Proxmox au complet

Le panneau d'un conteneur (ou d'une VM) gagne quatre blocs repliables :

- **Instantanés** : nom, date, *Retour* (deux appuis) et suppression ;
- **Disque** : disques détectés et agrandissement (`+2G` ou `16G`) ;
- **Sauvegardes** : archives de l'invité (taille, date, stockage), suppression,
  et lancement d'un `vzdump` en mode snapshot / suspend / stop ;
- **Cloner** : vmid proposé automatiquement, hostname, stockage cible.

L'onglet **Serveurs** ajoute, sous chaque nœud, quatre boutons : *Tâches* (liste,
journal complet, arrêt), *Journal* (`syslog`), *Modèles* (appliances LXC à installer)
et *Nœud…* (redémarrage / arrêt, double confirmation). Un compteur signale les tâches
en cours, et une notification arrive à la fin d'une sauvegarde, d'un clone ou d'un
instantané.

La liste des conteneurs se filtre : recherche texte (nom, vmid, tag) et pastilles
LXC / VM / en marche / arrêtés avec compteurs.

## Interface (mise à jour)

- **Console** : l'onglet ouvre le **shell du nœud Proxmox** ; un sélecteur permet de
  basculer sur une session tmux locale ou un conteneur (l'ancien bouton « main » en
  haut à droite a disparu).
- **Courbes cliquables** : appui sur une courbe → graphique en grand, plages
  heure/jour/semaine/mois, curseur et valeur exacte.
- **Conteneurs** : le panneau s'ouvre au clic, avec un bouton **Terminal** et
  l'interrupteur **démarrer au boot**.
- **Réglages** : sessions actives (IP, dernière activité, révocation), taille du
  texte, plein écran, état du conteneur, déconnexion.

## Connexion Proxmox sans configuration

Si le bloc `proxmox` n'a pas été écrit à l'installation, il se règle désormais
**depuis l'interface** : *Réglages → « IP du nœud Proxmox » → Enregistrer*
(`POST /api/pve/config`), sans passer par le shell.

L'installateur transmet l'IP du nœud : sur l'écran de connexion, tu tapes `root@pam`
et son mot de passe, **sans jeton d'API, sans clé SSH, sans rien configurer**.

Le ticket Proxmox renvoyé par `/access/ticket` est conservé côté serveur (2 h) et sert
à toutes les lectures et actions, **avec les droits de l'utilisateur connecté**. Le
certificat TLS du nœud est épinglé au premier contact (auto-signé accepté).

Le jeton d'API et la clé SSH restent facultatifs : le premier pour un accès en lecture
seule sans compte, la seconde pour ouvrir un shell dans un conteneur.

## Correctifs de la 1.0.1

- **connexion locale** : le champ « code de double authentification » s'affiche
  désormais en mode mot de passe local (il était exigé par le serveur mais jamais
  proposé — connexion impossible) ;
- **installation** : `runuser` remplace `sudo` (absent d'un Debian minimal), la
  configuration est bien générée et le service démarre ;
- **disque** : 4 Go par défaut au lieu de 1 Go (`No space left on device` pendant apt) ;
- **stockage** : sélection sur `content rootdir`, une clé USB « images » ne peut plus
  être choisie par erreur.

## Installation en une commande (dépôt public)

Sur le nœud Proxmox, en root — crée le conteneur 109 et installe tout :

```bash
CTID=109 bash -c "$(curl -fsSL https://raw.githubusercontent.com/heyhey2thereal/ServerDeck---Better-mobile-proxmox/main/packaging/create-lxc.sh)"
```

À la fin, l'installateur affiche un encadré avec l'**URL**, l'URL `.local`, le mot de
passe local, le secret TOTP, puis un **QR code** à scanner.

Le stockage est choisi parmi ceux qui acceptent les racines de conteneur (`rootdir`) —
une clé USB montée pour les sauvegardes ne sera donc pas prise. Pour forcer :

```bash
STORE=local-lvm CTID=109 bash -c "$(curl -fsSL https://raw.githubusercontent.com/heyhey2thereal/ServerDeck---Better-mobile-proxmox/main/packaging/create-lxc.sh)"
```

### Si le dépôt est privé

Ajoute un jeton en lecture (`Contents: read`) :

```bash
TOKEN=github_pat_xxx CTID=109 bash -c "$(curl -fsSL https://raw.githubusercontent.com/heyhey2thereal/ServerDeck---Better-mobile-proxmox/main/packaging/create-lxc.sh)"
```

### Détail manuel

```bash
pct create 109 local:vztmpl/debian-12-standard_12.7-1_amd64.tar.zst \
  --hostname serverdeck --cores 1 --memory 256 --swap 256 --rootfs local-lvm:4 \
  --net0 name=eth0,bridge=vmbr0,ip=dhcp --unprivileged 1 --features nesting=1 --onboot 1
pct start 109
pct exec 109 -- bash -c "apt-get update && apt-get install -y curl ca-certificates"
pct exec 109 -- bash -c "$(curl -fsSL https://raw.githubusercontent.com/heyhey2thereal/ServerDeck---Better-mobile-proxmox/main/get.sh)"
```

## Proxmox

**Rien à faire pour se connecter.** L'installateur enregistre l'IP du nœud ; tu te
connectes avec `root@pam` et ton mot de passe.

Pour les **shells de conteneurs** (facultatif), ajoute la clé SSH restreinte :

Le terminal du nœud et des conteneurs ne demande **aucune configuration** : le script
d'installation s'en charge, et pour un conteneur existant une seule commande suffit.

Sur le nœud Proxmox, en root :

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/heyhey2thereal/ServerDeck---Better-mobile-proxmox/main/packaging/enable-ssh.sh)"
```

Le script détecte le conteneur (nommé `serverdeck`), génère la clé, l'autorise avec la
commande restreinte (`host` | `ct <vmid>`) et redémarre le service.

Le script hôte crée le rôle `ServerDeck` (`VM.Audit, Sys.Audit, Datastore.Audit,
VM.PowerMgmt`), le jeton d'API et la commande SSH restreinte (`host` | `ct <vmid>`).
Le jeton n'est utile que si tu veux un accès en lecture seule sans compte.

## Contenu

**Terminal**
- xterm.js + PTY, sessions **tmux** persistantes ;
- barre de touches tactile (Esc, Tab, Ctrl/Alt *sticky*, flèches, Home/End, PgUp/PgDn,
  `|`, `~`, `/`, `-`) ;
- presse-papier complet : sélection + bouton, `Ctrl+Shift+C/V`, **OSC 52**
  (le copier de tmux arrive dans le presse-papier du téléphone) ;
- reconnexion automatique, écran maintenu allumé, PWA installable.

**Proxmox**
- ressources par nœud : CPU, mémoire, disque, uptime, version, courbe RRD ;
- liste LXC/VM, détail (cœurs, RAM, système, hostname, réseau), jauges, courbe ;
- actions démarrer / arrêter / couper / redémarrer ;
- shell dans chaque conteneur LXC, et shell du nœud si tu l'autorises.

**Connexion**
- identifiants **Proxmox** (`root@pam`, `utilisateur@pve`, LDAP/AD…) via
  `/access/ticket`, **sans configuration** : le ticket sert ensuite à l'API ;
- gestion de la **2FA** (le ticket partiel reste côté serveur) ;
- repli sur le mot de passe local + TOTP ; `"allowLocalLogin": false` pour le couper ;
- déconnexion réellement invalidante (sessions en mémoire) et certificat TLS épinglé.

**Pilotage Proxmox**
- instantanés, sauvegardes `vzdump`, clone, agrandissement de disque ;
- tâches avec journal et arrêt, notification de fin de tâche ;
- journal du nœud, modèles LXC, redémarrage / arrêt du nœud ;
- recherche et filtres dans la liste des conteneurs.

**Fichiers**
- onglet d'envoi, liste, renommage, suppression, téléchargement ;
- lien signé + commandes `wget`/`curl` pour un conteneur, collage direct dans son terminal.

**Interface**
- style Proxmox VE : fond clair, panneaux blancs, accents orange `#e57000` ;
- liens profonds : `/?view=nodes`, `/?view=guests`, `/?view=guests&guest=pve1|lxc|101` ;
- `"allowFrame": true` pour intégrer la console dans un dashboard (iframes).

## Sécurité

Terminal web = exécution de code à distance pour qui trouve l'URL. N'expose pas le
port 8090 sur Internet : **Tailscale** (recommandé) ou reverse proxy TLS avec TOTP
activé. Le service tourne en `serverdeck`, non-root.
